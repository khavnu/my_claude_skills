Traps hit (each cost a retry loop):
1. **Telex keyboard**: `adb shell input text Merge` types "Mểg". Tap the tile directly; only fall back to the search field.
2. **Landscape IME covers the tools list**: after typing in search, `keyevent 4` to hide the keyboard before tapping — otherwise the tap lands on a key ("Volumew").
3. **`grep -E` with labels like "Next (2)"**: parentheses are regex groups → NOT FOUND. Escape the label.
4. **Merged semantics**: a selectable Row (radio + text) exposes no text node → tap by coordinates.
5. **DocumentsUI picker survives `am force-stop` of the app**: relaunching resumes the stale picker. `am force-stop com.google.android.documentsui` first. Back inside the picker walks up its folders before leaving it.
6. **`uiautomator dump` costs ~1s per call** (2026-10-15). A tap-by-text helper dumps again before every tap, so a time-boxed flow (5s fake processing → Cancel → Stop) ran past the deadline and looked like an app bug. For timed flows: one dump, read every needed bounds from it, then chain `input tap x y` with short sleeps.
9. **The Pixel can be lying in landscape with auto-rotate on** (2026-10-16). Every fixed coordinate then misses. The sign is dump bounds with x > 1080 (for example `[236,441][2108,599]`). `cmd window user-rotation lock 0` did not stick. `settings put system accelerometer_rotation 0` + `user_rotation 0` did work, but auto-rotate came back on after about a minute (the user handling the phone?). Check `dumpsys window | grep mDisplayRotation` before a coordinate-driven flow.
   - Copying the source video into cache is very fast here: 725 MB took under 1 s. Killing the app "mid-copy" therefore needs a kill well under a second after the pick lands, so prove that path with a unit test instead.
8. **Text match `Tools` hits the wrong node right after launch** (2026-10-16). The tab label's bounds can be `[0,0][0,0]` while the pager settles, so the tap lands elsewhere. A swipe can then flip the pager to Library and focus its search field, and the IME swallows later swipes. Tap the bottom-nav icon by its coordinates instead (Pixel 9: `input tap 675 2317`, content-desc "Tools" at `[644,2286][707,2349]`). To keep long `connected` runs from uninstalling the app, use `installDebug installDebugAndroidTest` plus `am instrument -w -e class … <pkg>.test/androidx.test.runner.AndroidJUnitRunner`.
7. **`connectedDebugAndroidTest` uninstalls the app** → runtime permissions are gone on the next install (app opens on "Audio Access Needed"). After any instrumented run: `installDebug` + `pm grant <pkg> android.permission.READ_MEDIA_AUDIO / READ_MEDIA_VIDEO / POST_NOTIFICATIONS`.

Render a Composable on device without wiring it into the app: temporary androidTest probe with `createComposeRule().setContent { … }` + `uiAutomation.executeShellCommand("screencap -p /sdcard/Download/x.png")`, `adb pull`, delete the probe (it survives the uninstall because shell owns the file). Small test videos on the Pixel: `rename_repro.mp4` (2.5 MB, 2424x1080, folder "Unknown" in the picker); `Video_023.mov` is 725 MB (slow to cache).

**Emulator `Pixel_9` AVD (`emulator-5554`, Android 16), 2026-10-15:** it starts with no videos. Generate them on the host with `ffmpeg -f lavfi -i testsrc2=size=WxH:rate=30 -f lavfi -i sine=frequency=440 -t 8 -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest X.mp4`, push them to `/sdcard/Movies/`, then broadcast `MEDIA_SCANNER_SCAN_FILE`. Landscape 1920x1080, portrait 1080x1920 and 854x480 cover the resolution-label cases. The picker opens on "Recent" with the files listed. Its IME is a floating toolbar, so the rename sheet's buttons sit at y≈2300 rather than above a keyboard. The very first tap after the sheet opened once did nothing; this was not reproducible in 3 retries. Timed flows (Stop within 5s) need precomputed coordinates, because each `uiautomator dump` costs ~1s there too.


**Verify audio playback without listening (2026-10-16, Add audio preview):** `adb shell dumpsys audio | grep "u/pid:<app uid>"` lists each ExoPlayer's AudioTrack with `state:started|paused|idle` and `mutedState:clientVolume` when its volume is 0. That proved that two synced players start, pause and stop together, and that Replace mutes the video's track. To check an output's audio content, decode both files to 8 kHz mono PCM with ffmpeg and correlate them with numpy: corr 1.0 at lag 0 means the new audio starts at 00:00. Audio files sit under `/sdcard/Music/WMusiSamples/` on the emulator; look up `_data` with `content query --uri content://media/external/audio/media`.

**Emulator tricks (2026-10-26, tickets #446–#450):**
- Repro "navigation bar đè UI" ở landscape: emulator mặc định gesture nav → `adb shell cmd overlay enable-exclusive --category com.android.internal.systemui.navbar.threebutton`; trả lại bằng `...navbar.gestural`.
- `cmd window user-rotation lock N` chỉ ăn khi app đang ở foreground — gọi SAU khi launch, rồi kiểm `mRotation`.
- Khi kiểm cutout, chụp ảnh "trước khi sửa" phải chụp trên bản vừa `installDebug` + mở lại màn: lần đầu LibrarySelectScreen trông như đã pad cutout (instance cũ), cài lại mới lộ bug.

- **UiAutomation kẹt trên emulator-5554 (Android 16), 2026-10-26:** sau một lần `am instrument` chạy test có dùng UiAutomation (`PortraitRotationRule`, `uiAutomation.executeShellCommand`), lần chạy sau crash ngay khi khởi động: `UiAutomationService ... already registered!` / `Cannot call disconnect() while connecting UiAutomation` (đọc `adb logcat -d -b crash`). - **Đo âm lượng thực tế từng track (2026-10-27, #461):** `adb shell dumpsys media.audio_flinger | grep -E "Type +Id Active| yes +[0-9]+/ +<uid>"` → cột `L dB`/`R dB` (0 = 100%, -6 ≈ 50%, -inf = câm). In nguyên dòng kèm header, ĐỪNG awk theo số cột (độ rộng cột đổi theo giá trị, đã đọc lệch 2 lần). Chn mask 1 = mono (testsrc/sine video), 3 = stereo (mp3) để phân biệt track. Uid app lấy từ `u/pid:` trong `dumpsys audio`, không lấy `pm list -U` (khớp nhầm gói `.test`).

**Đo preview dừng/phát theo thời gian trên emulator (2026-11-02, #493/#494):**
- "Dừng ngay hay trễ": tap rồi poll `dumpsys audio | grep "u/pid:<uid>/" | grep AudioTrack | grep -oE 'state:[a-z]+'` liên tục (mỗi vòng ~15ms) → in mốc đổi trạng thái. #494 trước fix `started` tới +770ms (fade 700ms của NavDisplay), sau fix `paused` ở +36ms. Bản đối chứng: `git show <commit trước>:<file> > <file>` tạm cho đúng file, build, `git checkout HEAD -- <file>` trả lại.
- "Dừng đúng biên không lọt tiếng": emulator không nghe được → thêm 1 dòng Timber tạm (tag riêng) in `pos/end` lúc gọi pause, `logcat -s TAG:D`, gỡ log trước commit.
