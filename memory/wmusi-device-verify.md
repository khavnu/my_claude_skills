Any module with Compose UI tests needs `androidTestImplementation(libs.androidx.espresso.core)` (3.7+). Otherwise every test crashes on API 37 with NoSuchMethodException InputManager.getInstance.

A test whose content runs an infinite animation (spinning disc, animated equalizer) fails with ComposeNotIdleException. Set `composeRule.mainClock.autoAdvance = false` before `setContent`, then `advanceTimeBy(ms)` before capturing. Example: MediaAndListsTest (verified 2026-09-30).

JUnit4 androidTest written as `fun x() = runBlocking { ... }`: if the last expression is not Unit, the method is non-void and the whole class fails with "Failed to instantiate test runner class AndroidJUnit4ClassRunner" (root cause InvalidTestClassError). Use `runBlocking<Unit> { }`. Seen in :audio (was core/player) ExoPlayerEngineTest, 2026-09-30.

- Manual-only screenshot harness (2026-10-02, Now Playing Task 6, `NowPlayingWrapupScreenshotTest.kt`), verified by actually running it:
  - **`@Ignore` cannot be bypassed even with an explicit `-e class` filter** — confirmed: `connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=<FQCN>` on an `@Ignore`d class produced 0 testcases in the result XML. JUnit itself skips it regardless of how the runner is invoked. Use this project's existing `ManualRunOnly` convention instead (`audio`/`data` modules already have it): a plain custom annotation + `defaultConfig.testInstrumentationRunnerArguments["notAnnotation"] = "<pkg>.ManualRunOnly"` in the module's `build.gradle.kts`. `:app` didn't have this wired up before — added `app/src/androidTest/kotlin/com/wife/recommend/music/ManualRunOnly.kt` + the `notAnnotation` line in `app/build.gradle.kts`.
  - To actually run a `ManualRunOnly` class: `./gradlew :app:installDebug :app:installDebugAndroidTest` (installs only, no `notAnnotation` filter applied at install time), then a RAW `adb shell am instrument -w -e class <FQCN> com.wife.recommend.music.test/com.wife.recommend.music.HiltTestRunner` — bypasses the `notAnnotation` default arg entirely, since that arg is only injected by Gradle's own `connectedDebugAndroidTest` task, never by a direct `am instrument` call.
  - **`ScreenshotSupport`'s `additionalTestOutputDir` only works through Gradle's own `connectedDebugAndroidTest` task.** Passing `-e additionalTestOutputDir <any /sdcard/Android/data/... path>` by hand to a raw `am instrument` call fails with `FileNotFoundException: ... ENOENT` on every write — true even for a path the test process itself just `mkdirs()`'d, and even pointing at the package's own pre-existing `files/` dir. Root cause not fully isolated (scoped-storage FUSE quirk specific to paths not provisioned by AGP/UTP's own instrumentation setup), but the fix that works: write to `InstrumentationRegistry.getInstrumentation().targetContext.filesDir` (plain internal storage, no scoped-storage involvement) instead, then pull files after the run with `adb exec-out run-as <targetPackage> cat files/<name>.png > <name>.png` (needs a debuggable build, true for `debug`). Note `targetContext` is the **target app's** context (`com.wife.recommend.music`), not the `.test` package — `run-as` must use the target app's package name, not `<pkg>.test`.
